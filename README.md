# Filtrigen

Локальный бот, который читает твои личные Telegram-чаты и делает сводку важной
информации по заданной теме через локальную Ollama. Работает по кнопке —
никакого фонового мониторинга в реальном времени.

## Как это устроено

Два клиента в одном процессе:

- **userbot.py** — клиент Telethon, залогиненный ПОД ТВОИМ АККАУНТОМ (не отдельный
  бот Telegram). Именно поэтому он видит твою личную непубличную переписку —
  ровно то же, что видишь ты в приложении. После первого логина сессия
  сохраняется в файл, повторная авторизация не нужна.
- **controlbot.py** — обычный бот через @BotFather. Это твой пульт управления:
  кнопки, меню, ответы тебе в личку. Он дергает функции из userbot.py напрямую.

Логика "докачки" сообщений: для каждого отслеживаемого чата в SQLite хранится
`last_read_id` — id последнего прочитанного сообщения. При нажатии "Дать инфу"
бот запрашивает у Telegram все сообщения с `id > last_read_id` (через
`iter_messages(min_id=...)`), не важно, сколько времени комп был выключен.
После успешной сводки чекпоинт обновляется.

## Шаг 1. Получить необходимые ключи

1. **TG_API_ID / TG_API_HASH** — иди на https://my.telegram.org → "API development
   tools" → создай приложение (любое имя). Получишь `api_id` (число) и `api_hash`
   (строка).
2. **TG_BOT_TOKEN** — напиши @BotFather в Telegram → `/newbot` → следуй
   инструкциям → получишь токен вида `123456789:AA...`.
3. **TG_OWNER_ID** — напиши @userinfobot в Telegram, он пришлёт твой числовой
   `id`. Это нужно, чтобы control-бот отвечал только тебе, а не любому
   человеку, который его найдёт.

## Шаг 2. Настроить Ollama

Убедись, что Ollama установлена и модель скачана:

```bash
ollama pull llama3.1
ollama serve   # если ещё не запущена как сервис
```

Проверь, что она отвечает: `curl http://localhost:11434/api/tags`

## Шаг 3. Разложить файлы

Структура проекта (все файлы уже готовы):

```
filtrigen/
├── docker-compose.yml
├── Dockerfile
├── requirements.txt
├── db.py
├── userbot.py
├── controlbot.py
├── .env          <- создать из .env.example
└── data/         <- создастся автоматически, тут будут сессия и база
```

Скопируй `.env.example` в `.env` и заполни своими значениями:

```bash
cp .env.example .env
nano .env   # вписать TG_API_ID, TG_API_HASH, TG_BOT_TOKEN, TG_OWNER_ID
```

## Шаг 4. Собрать образ

```bash
docker compose build
```

## Шаг 5. Первый логин (обязателен, разовая процедура)

Контейнер в обычном режиме работает в фоне и не может спросить у тебя код
подтверждения. Поэтому первый логин делаем интерактивно, ОТДЕЛЬНОЙ командой,
до запуска через `up -d`:

```bash
docker compose run --rm filtrigen python -c "import asyncio, userbot; asyncio.run(userbot.interactive_login())"
```

Скрипт спросит:
- номер телефона (в международном формате, например `+79991234567`)
- код подтверждения, который придёт в Telegram
- пароль двухфакторной аутентификации, если он у тебя включён

После успеха увидишь `Успешно авторизован как: <имя>`. Файл сессии сохранится
в `./data/userbot.session` — он на хосте, переживёт пересборку контейнера.

**Больше логиниться не нужно** — если только не удалишь папку `data/`.

## Шаг 6. Запустить бота в фоне с автозапуском

```bash
docker compose up -d
```

`restart: unless-stopped` в docker-compose.yml гарантирует, что при
перезагрузке компьютера (и автозапуске Docker Desktop / Docker-демона)
контейнер поднимется сам. Ничего вручную включать не нужно.

Проверить, что всё работает:

```bash
docker compose logs -f
```

Должно быть: `controlbot запущен и опрашивает Telegram`.

## Шаг 7. Пользоваться

1. Найди своего control-бота в Telegram (по имени, которое дал при `/newbot`).
2. Напиши `/start`.
3. **⚙️ Настройки чатов → ➕ Добавить чат** — бот покажет список твоих
   последних диалогов (тянет их через userbot), выбираешь нужный.
4. После добавления сразу предложит **✏️ Задать тему** — напиши текстом,
   что тебя интересует, например: `дедлайны, оплаты, важные решения`.
5. Из главного меню **📥 Дать инфу** → выбираешь чат → бот подтягивает все
   новые сообщения с последнего чекпоинта, прогоняет через Ollama и
   присылает тебе сводку.
6. Если новых сообщений нет — так и напишет, чекпоинт не сдвинется зря
   (точнее сдвинется до текущего последнего id, что корректно).

Тему в любой момент можно поменять: **Настройки чатов → [чат] → ✏️ Изменить
тему**. Чат можно убрать из отслеживания там же (🗑).

## Важные нюансы

- **Это не нарушение шифрования** — секретные чаты (Secret Chat) Telethon
  читать не может в принципе (они end-to-end и живут только на устройствах-
  участниках), обычные же облачные чаты доступны, потому что они и так
  хранятся на серверах Telegram и доступны твоему аккаунту.
- **Риск ограничений аккаунта**: массовое автоматизированное использование
  userbot'ов не одобряется правилами Telegram. При редком использовании по
  кнопке (не сотни запросов в час) риск минимален, но не нулевой — это твой
  собственный аккаунт, действуй на свой страх и риск.
- **Первый запрос по новому чату** берёт только последние 50 сообщений (а не
  всю историю), дальше уже работает инкрементально от чекпоинта.
- **Ollama должна быть доступна из контейнера.** По умолчанию используется
  `http://host.docker.internal:11434` — это адрес хоста из контейнера,
  работает "из коробки" на Docker Desktop (Windows/Mac) и на Linux благодаря
  строчке `extra_hosts` в docker-compose.yml. Если Ollama слушает не на
  `0.0.0.0`/`localhost`, а на другом интерфейсе — поправь `OLLAMA_URL` в `.env`.
- **Модель Ollama** задаётся в `.env` (`OLLAMA_MODEL`) — можно поставить
  любую скачанную модель (`llama3.1`, `mistral`, `qwen2.5` и т.д.), чем
  больше контекст модели, тем больше сообщений она сможет переварить за раз.

## Остановка / обновление

```bash
docker compose down          # остановить
docker compose build         # пересобрать после правки кода
docker compose up -d         # запустить снова (сессия и база сохранятся)
```

## Возможные проблемы

- **"Сессия не авторизована"** — повтори Шаг 5.
- **"unable to open database file"** — убедись, что папка `data/` существует
  рядом с `docker-compose.yml` и что у Docker есть права на неё.
- **Бот не отвечает** — проверь `TG_OWNER_ID`: если он не совпадает с твоим
  реальным id, бот молча игнорирует все сообщения (это защита от чужих).
- **Ollama не отвечает из контейнера** — проверь `curl http://localhost:11434`
  на хосте, и что `OLLAMA_URL` в `.env` указывает правильно (для Linux иногда
  нужно `http://172.17.0.1:11434` вместо `host.docker.internal`, если
  `extra_hosts` не сработал — можно узнать IP хоста командой `ip addr show docker0`).
